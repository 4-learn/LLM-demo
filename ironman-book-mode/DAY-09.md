# Day 9｜組成簡單的 RAG 問答流程

> **定位**：用本地 Python 串起資料、檢索與回答草稿；理解實際 RAG 仍需 LLM、來源核對與安全處理。

## 學習目標

- 說出 RAG 的資料、檢索、生成步驟。
- 用本地文字查詢候選片段並保留來源。
- 知道檢索結果不足時應表示不知道。

## 概念

片段（chunk）是從較長文件切出的較小文字單位，用來檢索及提供上下文。Embedding（嵌入向量）是文字的數值表示，可供相似度檢索；本章程式僅用關鍵字比對，不是向量檢索。檢索只找候選資料，不保證候選內容完整或正確。

## 動手做：本地檢索與帶來源的回覆草稿

```python
docs = [
    {"source": "A", "text": "課程每週三下午上課。"},
    {"source": "B", "text": "作業請在週五前繳交。"},
]
query = "哪天上課"
hits = [d for d in docs if "上課" in d["text"]]
if hits:
    print("候選答案：", hits[0]["text"])
    print("來源：", hits[0]["source"])
else:
    print("資料不足，請查證。")
```

**實際輸出（以 Python 執行上述程式）：**

```text
候選答案： 課程每週三下午上課。
來源： A
```

這是關鍵字檢索，不是 embedding 或 LLM 生成。正式流程可把檢索到的片段與問題送給 OpenAI 相容 chat API，但只用核准的合成/公開資料，並要求模型引用來源；仍需驗證引用是否支持答案。

## 練習

查詢「作業何時繳交」，把檢索規則改為找到 `繳交`，並保留來源 B。再問資料沒有提到的問題，確認程式走「資料不足」分支。
