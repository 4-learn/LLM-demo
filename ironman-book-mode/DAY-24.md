# Day 24｜Dify 工作流：加入對話入口

> **定位**：在既有流程前加入對話輸入與回覆出口，辨識「工作流程」和「對話產品體驗」的差異。

## 學習目標
- 描述對話應用的輸入、流程執行與回覆路徑。
- 設計一個使用者看得懂的錯誤或查無資料回覆。
- 知道聊天 UI 不會自動使後端流程安全或正確。

## 概念
對話入口讓使用者以自然語言互動，流程仍需清楚的輸入欄位、分支條件和最終回覆。對模型或工具無法處理的情況，應告知使用者下一步，而不是編造結果。

UI（使用者介面）是使用者操作應用程式的畫面或互動方式；本章以 Python 模擬流程，不復現原文 Dify UI 點選步驟。Chatflow 是帶對話入口與回覆的工作流程，介面不會取代後端驗證。

## 動手做：用 Python 模擬對話路由

這段離線程式用固定分類規則展示入口、分支和回覆；不呼叫 Dify 或模型。

```python
def reply(message):
    text = message.strip()
    if not text:
        return "請輸入想查詢的活動。"
    if "活動" in text:
        return "已收到活動查詢；請提供名稱或日期以便查證。"
    return "目前只處理活動查詢，請補充活動關鍵字。"

for message in ("", "想查活動", "你好"):
    print(reply(message))
```

**實際輸出：**
```text
請輸入想查詢的活動。
已收到活動查詢；請提供名稱或日期以便查證。
目前只處理活動查詢，請補充活動關鍵字。
```

在紙上補上「外部查詢失敗」分支，標明哪一步會把資料送出服務，以及成功結果如何回查來源。

## 練習
以「查詢一筆公開活動資訊」為例，為成功、查無資料及服務失敗各寫一句不誤導使用者的回覆。
