# Day 19｜RAG 前先分類問題：分流、未知與 fallback

> **主題：** 依問題類型選擇檢索或處理路徑；分類器不確定時，應保留 fallback，而不是硬把問題分到錯誤知識庫。

RAG 是檢索增強生成，依文件檢索結果提供回答依據。Fallback（後備路徑）是分類不確定或處理失敗時採用的替代路徑，例如轉人工確認。本例的分類是關鍵字規則，不使用 LLM。

## 動手做：簡單分流基線

```python
def route(question):
    if "退貨" in question or "退款" in question:
        return "退貨知識庫"
    if "訂單" in question or "配送" in question:
        return "訂單知識庫"
    return "人工確認"

for q in ["怎麼申請退款？", "訂單配送到哪了？", "你們週末有開嗎？"]:
    print(f"{q} -> {route(q)}")
```

預期輸出：

```text
怎麼申請退款？ -> 退貨知識庫
訂單配送到哪了？ -> 訂單知識庫
你們週末有開嗎？ -> 人工確認
```

這是可檢查的關鍵字基線，會漏掉「商品不想要了」等同義問法。若改用 LLM 分類，也要建立固定測試案例、檢查錯誤分流，並保留未知/人工覆核路徑；分類結果不應授予工具權限。

## 小練習

測試「我想把買的東西退掉」及空字串。指出規則的漏判，並說明遇到未涵蓋問法時，為何人工確認比猜一個知識庫安全。
